## 2.1 集合与参数——「局面上有什么」

$$
\begin{aligned}
B &= \{L01\_1, L01\_2, L02\_1, L02\_2, L03\_1\} &&\text{5 块可用原材料} \\
H &= \{H01, H02, H03\} &&\text{备选订单} \\
J &= \{J01, \ldots, J07\} &&\text{工件类型} \\
O &= \{1,2,3,4,5,6\} &&\text{6 种摆放姿态} \\[4pt]
d_{h,j} &\quad \text{订单 } h \text{ 对工件 } j \text{ 的需求量} \\
s_j &\quad \text{工件 } j \text{ 的库存量} \\
p_j &\quad \text{工件 } j \text{ 的单件收益} \\
v_j &\quad \text{工件 } j \text{ 的单件体积}
\end{aligned}
$$

**每一行解释：**

- **B（5 块原材料）**：L01 有 2 块所以写成 `L01_1, L01_2`，L03 只有 1 块就 `L03_1`。这是「你能用的全部家当」。
- **H（3 个备选订单）**：三选一，这是你要做的第一个决策。
- **J（7 种工件）**：就是那 7 种产品规格。
- **O（6 种姿态）**：一个长方体工件可以旋转摆放。长宽高三个轴，每个轴可以朝上，共 3×2=6 种方向。比如 40×40×40 的正方体 6 种姿态都一样，但 J07（120×20×20）旋转后摆放位置完全不同。
- **$d_{h,j}$**：比如 $d_{H01, J04} = 54$，表示 H01 订单需要 54 个 J04。
- **$s_j$**：比如 $s_{J03} = 20$，仓库里躺着 20 个 J03 现成的。
- **$p_j$**：卖一个赚多少钱。$p_{J04} = 1850$。
- **$v_j$**：一个占多少体积。$v_{J04} = 75 \times 60 \times 40 = 180{,}000$。

## 2.2 决策变量——「你要决定什么」

$$
\begin{aligned}
select_h &\in \{0, 1\} &&\sum_h select_h = 1 \\[4pt]
produce_{b,j,k,o} &\in \{0, 1\} &&\text{块 } b \text{ 中以姿态 } o \text{ 生产工件 } j \text{ 的第 } k \text{ 个实例} \\[4pt]
emergency_{h,j} &\in \mathbb{Z}^+ &&\text{紧急采购量} \\[4pt]
x_{b,j,k},\; y_{b,j,k},\; z_{b,j,k} &\geq 0 &&\text{摆放坐标}
\end{aligned}
$$

### ① $select_h$ —— 选哪个订单

三个里只能选一个，所以 $\sum select_h = 1$（只有一个 $select$ 是 1，其余是 0）。这是整个问题的**第一层决策**。

### ② $produce_{b,j,k,o}$ —— 在哪块材料上、用什么姿态、生产什么工件

这个变量下标最多，拆开看：

```
produce_{b, j, k, o}
         │  │  │  └── 用哪种旋转姿态（6选1）
         │  │  └───── 该工件的第几个实例（第1个J04、第2个J04...）
         │  └──────── 哪种工件（J01~J07）
         └─────────── 在哪块原材料上（L01_1~L03_1）
```

它是一个 **0/1 变量**——要么在这块材料的这个位置以这个姿态放这个工件，要么不放。

**为什么需要 $k$？** 因为同一个订单可能要生产 54 个 J04，你需要区分「第 1 个 J04」和「第 54 个 J04」，它们放在不同位置。

### ③ $emergency_{h,j}$ —— 紧急采购多少个

正整数。选 H03 的话，J06 自产不够就紧急采购几个。这个变量是你「赔钱的来源」。

### ④ $x, y, z$ —— 每个工件的摆放坐标

每个生产出来的工件 $(b,j,k)$ 在原材料块里的**左下角坐标**。这是 3D 装箱的核心——你不仅要决定「放不放」，还要决定「放哪里」。

## 2.3 约束条件——「不能乱来」

### 约束 (a)：订单唯一性

$$\sum_{h \in H} select_h = 1$$

三个订单必须且只能选一个。

---

### 约束 (b)：需求满足

$$s_j + \sum_{b \in B} \sum_{k} \sum_{o \in O} produce_{b,j,k,o} + emergency_{h,j} \geq d_{h,j} \cdot select_h$$

看起来很复杂，拆开就是：

```
仓库里已有的  +  自己生产的  +  紧急采购的  ≥  订单要求的
    s_j            ∑produce      emergency      d_{h,j}
```

- **库存**：白送的，不需要生产
- **自产**：所有 5 块材料上所有姿态下生产的该工件总数
- **采购**：实在不够就赔钱买
- **右边乘了 $select_h$**：只有被选中的那个订单的需求才生效

---

### 约束 (c)：空间边界——「不能超出原材料」

$$
\begin{cases}
x_{b,j,k} + l_j' \leq L_b \\
y_{b,j,k} + w_j' \leq W_b \\
z_{b,j,k} + h_j' \leq H_b
\end{cases}
$$

意思：**工件的右边界不能超出原材料的右边界**。

```
原材料 L01: 300 × 200 × 150
         ┌──────────────────┐
         │                  │
         │   ┌──────┐       │
         │   │ 工件  │       │  x + 工件长 ≤ 300 ✓
         │   └──────┘       │  如果超出 → 工件伸到材料外面 → 不合法
         │                  │
         └──────────────────┘
```

$(l_j', w_j', h_j')$ 是工件以姿态 $o$ 旋转后的实际长宽高，带撇表示「旋转后的尺寸」。

---

### 约束 (d)：不重叠——「工件不能穿模」

> 同一原材料块中任意两个不同工件，至少满足以下之一：

$$
\begin{aligned}
x + l' \leq x' \;\lor\; x' + l'' \leq x \;\lor\; y + w' \leq y' \;\lor\; y' + w'' \leq y \;\lor\; z + h' \leq z' \;\lor\; z' + h'' \leq z
\end{aligned}
$$

这 6 个条件用了**析取（OR）**关系——只要满足**任意一个**，两个工件就不重叠：

```
条件1: 工件1的右边界 ≤ 工件2的左边界     → 工件1在工件2左边（X轴分离）
条件2: 工件2的右边界 ≤ 工件1的左边界     → 工件1在工件2右边（X轴分离）
条件3: 工件1的后边界 ≤ 工件2的前边界     → 工件1在工件2前面（Y轴分离）
条件4: 工件2的后边界 ≤ 工件1的前边界     → 工件1在工件2后面（Y轴分离）
条件5: 工件1的上边界 ≤ 工件2的下边界     → 工件1在工件2下面（Z轴分离）
条件6: 工件2的上边界 ≤ 工件1的下边界     → 工件1在工件2上面（Z轴分离）
```

图示（俯视图，只看 X 和 Y 两个维度）：

```
  条件1：工件1在左             条件2：工件1在右
  ┌──┐  ┌──┐                ┌──┐  ┌──┐
  │ 1│  │ 2│                │ 2│  │ 1│
  └──┘  └──┘                └──┘  └──┘
  x1+l1 ≤ x2 ✓             x2+l2 ≤ x1 ✓

  条件5：工件1在下             条件6：工件1在上
    ┌──┐                        ┌──┐
    │ 2│                        │ 1│
    └──┘                        └──┘
    ┌──┐                        ┌──┐
    │ 1│                        │ 2│
    └──┘                        └──┘
  z1+h1 ≤ z2 ✓             z2+h2 ≤ z1 ✓
```

**核心逻辑**：只要两个工件在 X、Y、Z 三个方向中任意一个方向上是分开的，它们就不重叠。这正是「析取约束」的含义——6 个条件至少成立一个。

## 2.4 目标函数——「你要最大化什么」

$$\Pi_h = \underbrace{\sum_j p_j \cdot \min(s_j, d_{h,j})}_{\text{库存利润（白赚）}} \;+\; \underbrace{\sum_j p_j \cdot produced_j}_{\text{自产利润}} \;-\; \underbrace{\sum_j p_j \cdot emergency_{h,j}}_{\text{紧急采购净损失}}$$

三项拆开：

| 项 | 公式 | 什么意思 |
|----|------|---------|
| **库存利润** | $p_j \times \min(s_j, d_{h,j})$ | 仓库里已有的工件，最多用到订单需要的量（多了也不能全用），直接交货，**零成本，纯赚** |
| **自产利润** | $p_j \times produced_j$ | 用剩余原材料自己生产的，原材料成本已沉没（已经买过了），所以也**全赚** |
| **采购损失** | $p_j \times emergency_j$ | 花 $2p_j$ 买进来，卖出去得 $p_j$，**净亏 $p_j$**，所以要减去 |

**注意**：第二项不是「收入减成本」——原材料已经买过了，成本是沉没成本，不参与决策。这个概念是题目隐含的：原材料已经在你仓库里了，不用就是浪费。

---

## 模型的逻辑结构总结

```
决策层1: 选哪个订单？    select_h ∈ {0,1}, Σselect_h = 1
                ↓
决策层2: 怎么排产？      produce_{b,j,k,o}  +  x,y,z 坐标
                ↓
决策层3: 不够怎么办？    emergency_{h,j}（赔钱补缺口）
                ↓
目标: 最大化 库存利润 + 自产利润 - 采购损失
```

---

## 为什么这个模型没法「直接求解」

这个数学模型写了四类约束，看起来很漂亮，但它是**混合整数非线性规划（MINLP）**：

- **整数变量**：$select_h$, $produce_{b,j,k,o}$, $emergency$
- **连续变量**：$x, y, z$ 坐标
- **析取约束 (d)**：6 个 OR 条件，标准的「大 M 法」处理也要引入大量辅助 0/1 变量
- **规模**：仅 $produce$ 变量就有 $5 \text{ 块} \times 7 \text{ 种} \times \text{每种几十个} \times 6 \text{ 姿态}$ ≈ 数千个 0/1 变量

**这就是为什么你不能把它扔进求解器直接算，而要用 Beam Search 做启发式求解。** 数学模型的作用是**精确描述问题**——让读者明白「你在解什么」；算法是**实际求解的工具**——解决「怎么解」。

这也是数学建模竞赛论文的标准写法：先建模型（定义清楚变量和约束），再设计算法（因为模型太复杂解不动），两者独立但呼应。

## 补充细节

### 为什么库存利润用 $\min(s_j, d_{h,j})$？

仓库里 J03 有 20 个，但 H01 只需要 24 个 J03。如果你选的是 H02（它需要 70 个 J03），这 20 个库存全部能用上。但换个订单，比如某个只需要 5 个 J03 的，你就只能用掉 5 个库存——多余的库存不能变现，因为订单不需要。所以是「取两者最小值」。

### 紧急采购为什么净亏 $p_j$ 而不是 $2p_j$？

- 采购成本：支付 $2p_j$（题目规定：紧急采购产生 2 倍收益的额外成本）
- 交货收入：拿到 $p_j$
- 净贡献：$+p_j - 2p_j = -p_j$

目标函数里直接写 $-p_j \times emergency_j$，已经扣掉了。
