# 多策略贪心算法详解

> 配合 `subproblem3_beamsearch.py` 中的 `solve_order_greedy()`, `generate_orderings()`, `solve_order_multi()` 阅读。

---

## 一、核心思想

一句话：**对同一个问题，用不同的顺序装箱，取最好的结果。**

就像搬家往车里装东西：
- 先放大箱子再放小箱子 → 小箱子可能塞不进缝隙
- 先放小箱子再放大箱子 → 大箱子可能没位置了
- 两种都试，选装得多的那种

---

## 二、算法流程

### 2.1 伪代码

```
输入: 订单需求 order_demand

1. 生成 N 种放置顺序 orderings
   - 利润密度升序/降序
   - 体积升序/降序
   - 混合策略 (高→低→中)
   - 关键排列 (先锁高利润再填小工件)
   - 随机排列 (固定种子, 可复现)

2. best_result = None

3. 对每种顺序 ordering:
     创建 5 块空材料 (BlockPacker)
     对 ordering 中每种工件 wp:
       循环:
         在 5 块材料中找 gap 最小的位置 (Best-Fit)
         如果放得下 → 放入, 继续
         如果放不下 → 换下一种工件
     计算净利润
     如果比 best_result 好 → 更新

4. 返回 best_result
```

### 2.2 三步拆解

```
第一步: 生成 36 种放置顺序
         ┌──────────────────────────────────────┐
         │ 利润密度升序: J01→J02→J03→J05→J07    │
         │ 利润密度降序: J07→J05→J03→J02→J01    │
         │ 体积升序:     J07→J01→J02→J03→J05    │
         │ 混合策略:     J05→J01→J02→J03→J07    │
         │ 随机排列 × 30                         │
         └──────────────────────────────────────┘
                          ↓
第二步: 每种顺序用贪心 Best-Fit 打包
         ┌──────────────────────────────────────┐
         │ 顺序 [8] J05→J01→J02→J03→J07:       │
         │   放 J05×8  → 利润 +20,160           │
         │   放 J01×48 → 利润 +29,760           │
         │   放 J02×190→ 利润 +148,200          │
         │   放 J03×50 → 利润 +44,000           │
         │   放 J07×32 → 利润 +17,280           │
         │   采购 J02×10+J07×5 → 损失 -10,500  │
         │   净利润 = 295,320                    │
         └──────────────────────────────────────┘
                          ↓
第三步: 取所有顺序中净利润最高的
         ┌──────────────────────────────────────┐
         │ 最优: 顺序 [8] J05→J01→J02→J03→J07  │
         │ 净利润: 295,320                       │
         │ 利用率: 94.01%                        │
         └──────────────────────────────────────┘
```

## 三、单次贪心过程演示

以 H02 订单、顺序 `[8] J05→J01→J02→J03→J07` 为例：

### 步骤 1：放置 J05（需要 8 个，利润密度 0.01050）

```
J05 是 80×60×50 的大工件，利润最高 (2520/个)。
先放它，锁住核心利润。

  第 1 个 → L03_1  姿态 80×60×50  gap=240
  第 2 个 → L03_1  姿态 80×60×50  gap=40
  ...
  第 8 个 → L02_1  姿态 80×60×50  gap=200

小计: 8/8 个全部放完  利润 +20,160  利用率 6.88%
```

J05 只有 8 个，放在角落，占总体积 1,920,000（仅 6.9%）。**大空间还在。**

### 步骤 2：放置 J01（需要 48 个，利润密度 0.00969）

```
J01 是 40×40×40 的小工件，利润密度最低。
但现在大空间还在，趁机大量塞入。

  第 1 个 → L03_1  姿态 40×40×40  gap=30
  第 2 个 → L03_1  姿态 40×40×40  gap=30
  ...
  第 48 个 → L02_2  姿态 40×40×40  gap=10

小计: 48/48 个全部放完  利润 +29,760  利用率 17.89%
```

**关键**：如果先放了 J07/J05 占满大空间，J01 就放不下了。先放 J05（只有 8 个）再放 J01，两全其美。

### 步骤 3：放置 J02（需要 200 个，利润密度 0.00975）

```
J02 是 50×40×40 的小工件，需要 200 个（数量最多）。
继续用剩余空间大量填入。

  第 1 个 → L02_2  姿态 50×40×40  gap=270
  ...
  第 190 个 → ...
  放了 190 个后放不下了

小计: 190/200 个已放置  利润 +148,200  利用率 72.37%
```

空间开始紧张了。还差 10 个 J02，后面看能不能用碎片空间补。

### 步骤 4：放置 J03（需要 50 个，利润密度 0.00978）

```
J03 是 60×50×30 的中等工件。
用碎片空间继续填。

  第 1 个 → L03_1  姿态 60×30×50  gap=140
  ...
  第 50 个 → L01_2  姿态 60×50×30  gap=60

小计: 50/50 个全部放完  利润 +44,000  利用率 88.50%
```

### 步骤 5：放置 J07（需要 37 个，利润密度 0.01125）

```
J07 是 120×20×20 的细长工件。
填最后的缝隙。

  第 1 个 → L02_1  姿态 120×20×20  gap=70
  ...
  第 32 个 → ...
  放了 32 个后放不下了

小计: 32/37 个已放置  利润 +14,580  利用率 94.01%
```

### 最终统计

```
工件     需要   自产   采购   利润贡献
J01       48     48      0    29,760
J02      200    190     10   140,400
J03       50     50      0    44,000
J05        8      8      0    20,160
J07       37     32      5    14,580

库存利润:     46,420
自产利润:    259,400
采购损失:     10,500  (J02×10 + J07×5)
净利润:      295,320  ✅
利用率:       94.01%
```

## 四、为什么不同顺序结果差异巨大

### 4.1 六种策略对比

| 策略 | 顺序 | 净利润 | 采购损失 | 利用率 | 采购详情 |
|:-----|:-----|-------:|--------:|------:|:---------|
| 利润密度升序 | J01→J02→J03→J05→J07 | 276,000 | 20,160 | 90.85% | J05×8 |
| 利润密度降序 | J07→J05→J03→J02→J01 | 225,600 | 45,360 | 80.99% | J01×48, J02×20 |
| 高利润优先 | J05→J03→J02→J01→J07 | 249,000 | 33,660 | 85.29% | J01×48, J02×5 |
| 小体积优先 | J07→J01→J02→J03→J05 | 258,400 | 28,960 | 87.63% | J03×10, J05×8 |
| **混合(最优)** | **J05→J01→J02→J03→J07** | **295,320** | **10,500** | **94.01%** | **J02×10, J07×5** |
| 交替 | J01→J02→J05→J03→J07 | 276,000 | 20,160 | 90.85% | J05×8 |

### 4.2 核心矛盾

```
先放高利润工件 (J05/J07):
  ┌────────────────────────────────────┐
  │ J07 J07 J07 J07 ... J05 J05 J05  │ ← 大空间被占满
  │ J07 J07 J07 J07 ... J05 J05 J05  │
  │ ... 碎片化空间 ...                  │ ← 剩余空间被切成窄条
  │ J01 放不下! J02 放不下!             │ ← 小工件全部紧急采购
  └────────────────────────────────────┘
  结果: J01×0, J02×174  利润 216,240 ← 最差!

先放小工件 (J01/J02):
  ┌────────────────────────────────────┐
  │ J01 J01 J01 J01 J01 J01 J01 J01  │ ← 小工件填满大空间
  │ J02 J02 J02 J02 J02 J02 J02 J02  │
  │ J02 J02 J02 J02 J02 J02 J02 J02  │
  │ ... 没有大空间了 ...                │ ← J05 放不下
  └────────────────────────────────────┘
  结果: J05×0  利润 276,000 ← 中等

先放 1 个大工件, 再放小工件:
  ┌────────────────────────────────────┐
  │ J05 J05 J05 J05 J05 J05 J05 J05  │ ← 第1步: 只放 8 个 J05 (占 6.9%)
  │                                   │
  │ J01 J01 J01 J01 J01 J01 J01 J01  │ ← 第2步: 大空间还在, 放 48 个 J01
  │ J02 J02 J02 J02 J02 J02 J02 J02  │ ← 第3步: 继续放 190 个 J02
  │ J03 J03 J07 J07 ...               │ ← 第4-5步: 填缝隙
  └────────────────────────────────────┘
  结果: J01×48, J02×190  利润 295,320 ← 最优!
```

**关键洞察**：J05 只有 8 个，放在角落不占太多空间（6.9%）。然后 J01/J02 趁大空间还在，大量塞入。最后用 J03/J07 填缝隙。这种"先锁少量高利润 → 再填大量低利润 → 最后补中等"的策略，单一排序发现不了，需要多策略探索。

## 五、与 Beam Search 的对比

### 5.1 计算量对比

| | Beam Search | 多策略贪心 |
|---|---|---|
| **深拷贝次数** | **32,896** | **0** |
| **try_place 次数** | 32,896 | ~11,808 |
| **总耗时** | 4,600ms | **99ms** |

### 5.2 为什么多策略贪心更快？

```
Beam Search:
  每轮: 10 个状态 × 5 块 × 8 候选 = 400 次深拷贝
  深拷贝: 复制 5 个 BlockPacker (每个含 ~50-100 个 Space 对象)
  迭代: ~270 轮
  总计: ~108,000 次深拷贝 + ~108,000 次 try_place

多策略贪心:
  每次贪心: 170-328 次 try_place (无深拷贝!)
  策略数: 36
  总计: ~11,808 次 try_place

  深拷贝 = 内存分配 + 对象复制 + GC 压力 → 最大的性能瓶颈
  多策略贪心不需要深拷贝 → 快 46 倍
```

### 5.3 为什么多策略贪心结果更好？

```
Beam Search 的问题:
  每步按"总利润"排序选 top-K 状态
  → 放 J05 (+2520) 的分支 利润 > 放 J01 (+620) 的分支
  → J01 的分支永远被淘汰
  → J01 全部紧急采购
  → K=1 到 K=100 结果完全相同 (不是搜索宽度问题)

多策略贪心的优势:
  不同放置顺序 = 不同的探索路径
  "先放 J05 再放 J01" 是一种特定顺序
  → 贪心会尝试这种顺序
  → J01 被成功放入
  → 利润大幅提升
```

### 5.4 结果对比

| 订单 | Beam Search | 多策略贪心 | 提升 |
|:----:|:-----------:|:---------:|:----:|
| H01 | 285,620 | 285,620 | 0 |
| **H02** | 216,240 | **295,320** | **+79,080 (+36%)** |
| H03 | 266,460 | 266,460 | 0 |
| **最优订单** | H01 (错误) | **H02 (正确)** | — |
| **总耗时** | 4.6s | **0.3s** | **15x 快** |

## 六、放置顺序是怎么生成的

`generate_orderings()` 函数生成 6 类策略：

### 6.1 基础排序（8 种）

```python
# 按某个指标升序/降序排列所有工件
by_profit_density      # 利润密度升序: J01→J02→J03→J05→J07
by_profit_density_desc # 利润密度降序: J07→J05→J03→J02→J01
by_volume              # 体积升序:     J07→J01→J02→J03→J05
by_volume_desc         # 体积降序:     J05→J03→J02→J01→J07
by_profit              # 利润升序:     J07→J01→J02→J03→J05
by_profit_desc         # 利润降序:     J05→J03→J02→J01→J07
by_demand              # 需求量升序:   J05→J03→J07→J01→J02
by_demand_desc         # 需求量降序:   J02→J01→J07→J03→J05
```

### 6.2 混合策略（6 种）

```python
# 将工件按利润密度分为三组:
#   高 (≥0.01050): J05, J07
#   中 (0.00980~0.01050): J03
#   低 (<0.00980): J01, J02

# 三组的 6 种排列:
high + low + mid   # 先锁高利润, 再填低利润, 最后补中等
high + mid + low
low + high + mid
low + mid + high
mid + high + low
mid + low + high
```

### 6.3 关键排列（6 种）

```python
# 每种高利润工件开头, 剩余按利润密度升序
J05 + [J01, J02, J03, J07]  # ← 最优策略就在这里
J07 + [J01, J02, J03, J05]

# 每种低利润工件开头, 剩余按利润降序
J01 + [J05, J03, J07, J02]
J02 + [J05, J03, J07, J01]
```

### 6.4 关键发现排列（3 种）

```python
# 从分析中发现的最优模式: 先 J05, 再 J01+J02, 再其他
J05 → J01 → J02 → [剩余按利润密度升序]
J05 → J02 → J01 → [剩余按利润密度升序]
J05 → J01 → J02 → [剩余按利润密度降序]
```

### 6.5 随机排列（30 种）

```python
# 固定种子 42, 保证可复现
rng = random.Random(42)
for _ in range(30):
    perm = list(wp_names)
    rng.shuffle(perm)
    orderings.append(perm)
```

去重后共 36 种排列。每次贪心 ~2ms，36 次共 ~77ms。

## 七、Best-Fit 贪心打包详解

每种工件的放置过程：

```
目标: 在 5 块材料中放 target 个工件

循环:
  1. 对每块材料的每种旋转姿态:
     找到所有能容纳该工件的空间
     选 gap 最小的那个 (Best-Fit)

  2. 在所有块、所有姿态中, 选全局 gap 最小的

  3. 放入工件, 更新空间

  4. 如果所有块都放不下 → 停止, 记录已放数量
```

gap = (空间长 - 工件长) + (空间宽 - 工件宽) + (空间高 - 工件高)

gap 越小 = 工件和空间越贴合 = 空间浪费越少。

## 八、总结

```
多策略贪心 = 排列组合穷举「先放什么后放什么」
           × 每种顺序用 Best-Fit 贪心装箱
           × 取最优结果

优势:
  ✅ 突破利润排序局限 → H02 找到更优解
  ✅ 无深拷贝 → 比 Beam Search 快 46 倍
  ✅ 代码简单 → 易理解和调试
  ✅ 确定性 → 固定种子可复现

局限:
  ⚠️ 仍然是贪心 → 不保证全局最优
  ⚠️ 依赖排列覆盖 → 可能遗漏某些好顺序
  ⚠️ 每种工件连续放 → 不支持工件间交替放置

适用场景:
  - 利润导向的 3D 装箱问题
  - 工件种类少 (5-10 种), 每种数量多
  - 不同工件的利润密度差异大
  - 需要快速求解 (秒级)
```
