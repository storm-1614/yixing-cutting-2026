### 1.5 紧急采购规则

- 自产：获得收益 $+p_j$，原材料成本已沉没，不计

## 二、数学模型

### 2.1 集合与参数

$$
\begin{aligned}
B &= \{L01\_1, L01\_2, L02\_1, L02\_2, L03\_1\} &&\text{5 块可用原材料} \\
H &= \{H01, H02, H03\} &&\text{备选订单} \\
J &= \{J01, \ldots, J07\} &&\text{工件类型} \\
O &= \{1,2,3,4,5,6\} &&\text{6 种摆放姿态} \\[4pt]
d_{h,j} &\quad \text{订单 } h \text{ 对工件 } j \text{ 的需求量} \\
s_j &\quad \text{工件 } j \text{ 的库存量} \\
p_j &\quad \text{工件 } j \text{ 的单件收益} \\
v_j &\quad \text{工件 } j \text{ 的单件体积}
\end{aligned}
$$

### 2.2 决策变量

$$
\begin{aligned}
select_h &\in \{0, 1\} &&\sum_h select_h = 1 \\[4pt]
produce_{b,j,k,o} &\in \{0, 1\} &&\text{块 } b \text{ 中以姿态 } o \text{ 生产工件 } j \text{ 的第 } k \text{ 个实例} \\[4pt]
emergency_{h,j} &\in \mathbb{Z}^+ &&\text{紧急采购量} \\[4pt]
x_{b,j,k},\; y_{b,j,k},\; z_{b,j,k} &\geq 0 &&\text{摆放坐标}
\end{aligned}
$$

### 2.3 约束条件

**(a) 订单唯一性**

$$
\sum_{h \in H} select_h = 1
$$

**(b) 需求满足**：库存 + 自产 + 紧急采购 ≥ 订单需求

$$
s_j + \sum_{b \in B} \sum_{k} \sum_{o \in O} produce_{b,j,k,o} + emergency_{h,j} \geq d_{h,j} \cdot select_h, \quad \forall j \in J,\; \forall h \in H
$$

**(c) 空间边界**

$$
\begin{cases}
x_{b,j,k} + l_j' \leq L_b \\
y_{b,j,k} + w_j' \leq W_b \\
z_{b,j,k} + h_j' \leq H_b
\end{cases}
$$

**(d) 不重叠（析取约束）**

同一原材料块中任意两个不同工件实例 $(j,k)$ 与 $(j',k')$，至少满足以下之一：

$$
\begin{aligned}
x + l' \leq x' \;\lor\; x' + l'' \leq x \;\lor\; y + w' \leq y' \;\lor\; y' + w'' \leq y \;\lor\; z + h' \leq z' \;\lor\; z' + h'' \leq z
\end{aligned}
$$

### 2.4 目标函数

$$
\Pi_h = \underbrace{\sum_j p_j \cdot \min(s_j, d_{h,j})}_{\text{库存利润（白赚）}} \;+\; \underbrace{\sum_j p_j \cdot produced_j}_{\text{自产利润}} \;-\; \underbrace{\sum_j p_j \cdot emergency_{h,j}}_{\text{紧急采购净损失}}
$$

$$
h^* = \arg\max_{h \in H} \Pi_h
$$

> 紧急采购的经济学解释：支付 $2p_j$ 成本买入 → 交货获得 $p_j$ 收入 → 净贡献为 $-p_j$。

## 四、求解算法：多策略贪心 + EMS

### 4.1 单一贪心的缺陷

```
单一贪心 (固定排序):
  每步在所有候选工件中选"当前最紧密贴合"的 1 个放入
  → 一条路径走到底，不回头
  → 如果早期选了看似最优但堵死后续的工件，无法撤销

  例: step1 放了 J05(80×60×50)，因为"最贴合"当前空间
      但这个 J05 切成左右两个窄条空间，导致后面 10 个 J06 放不下
      如果能"看到后面"，step1 应该放 3 个 J06 而不是 1 个 J05
```

### 4.2 Beam Search 的局限性

Beam Search 试图通过保留 K 条路径来解决单一贪心的问题，但它有一个**结构性缺陷**：

```
Beam Search 的排序机制:
  每步按"总利润"排序 → 保留 top-K 状态

  → 放 J05 (+2520) 的分支 利润 > 放 J01 (+620) 的分支
  → J01 的分支永远被淘汰
  → J01 全部紧急采购

  K=1 到 K=100 结果完全相同 → 不是搜索宽度问题
  → 是排序规则的问题: 利润排序系统性排斥低利润工件
```

### 4.3 多策略贪心的核心思想

```
多策略贪心 (Multi-Strategy Greedy):

  对每个订单，生成 ~80 种不同的工件放置顺序:
    - 按利润密度升序/降序
    - 按体积升序/降序
    - 混合策略: 高利润→低利润→中利润
    - 关键排列: 先锁高利润再填小工件
    - 随机排列 (固定种子, 可复现)

  对每种顺序，用贪心 Best-Fit 打包:
    → 按指定顺序依次放置每种工件
    → 每个工件在所有 5 块材料中找最佳位置
    → 放完一种再放下一种

  取所有顺序中净利润最高的结果
```

**关键优势**：不同放置顺序探索完全不同的打包空间。"先放低利润"可以为小工件预留空间，"先放高利润"可以锁住核心利润。两种策略的解空间几乎不重叠。

### 4.3 状态表示

```
BeamState {
    packers:    [BlockPacker × 5]   // 5 块原材料当前填充状态（空间列表+已放工件）
    placed:     {J01→12, J04→38…}  // 各工件已生产数量
    profit:     185,200             // 当前总利润
    depth:      87                  // 已放置工件数
}
```

### 4.4 算法伪代码

```
输入: 订单 h, 参数 K=10, M=8, max_iter=300

1. need = {j: max(0, d_{h,j} - s_j)}    // 需生产量
2. items = 按需生产量展开工件列表 (含 6 种姿态候选), 按利润降序
3. beam = [空状态 ×5块], best = 空状态

4. while beam 非空 and iter < max_iter:
     candidates = []
     for state in beam:
         for 每个 block in state.packers:
             找到当前 block 中能放入的 top-M 个工件  // Best-Fit 评分
             for 每个候选工件 (name, dx, dy, dz):
                 new_state = deep_copy(state)
                 new_state.packers[block].try_place(name, dx, dy, dz)
                 new_state.placed[name] += 1
                 new_state.profit += WP_MAP[name].profit
                 candidates.append(new_state)

     if candidates 为空: break

     candidates.sort(by=profit, descending)
     if candidates[0].profit > best.profit: best = candidates[0]
     beam = candidates[:K]

5. produced   = best.placed
   emergency  = {j: max(0, d_{h,j} - s_j - produced[j])}
   net_profit = stock_profit + sum(p_j * produced[j]) - sum(p_j * emergency[j])

6. return {produced, emergency, net_profit}
```

### 4.5 复杂度

$$
\begin{aligned}
\text{每轮扩展} &= K \times N_{\text{blocks}} \times M = 10 \times 5 \times 8 = 400 \text{ 个新状态} \\
\text{总扩展数} &\leq 400 \times 300_{\text{max\_iter}} = 120{,}000 \\
\text{每次扩展} &= \text{深拷贝 Packer} + \text{单次 EMS 放置} \\
\text{总耗时（每订单）} &\approx 30\text{--}60\text{s}
\end{aligned}
$$

### 4.6 三种算法对比

| 维度 | EMS 贪心 | Beam Search | **多策略贪心** |
|:-----|:---------|:------------|:---------------|
| **每步选择** | 选 1 个最优工件 | 从 M=8 个候选中各创建分支 | **按指定顺序依次放置** |
| **保留路径** | 1 条 | K=10 条 | **80 种顺序 × 1 条** |
| **本质** | 固定排序贪心 | 利润排序的树搜索 | **排列空间搜索** |
| **回溯能力** | 无 | 其他分支可能幸存 | **不同顺序=不同路径** |
| **低利润工件** | 可能被挤掉 | **被系统性排斥** | **可被优先放置** |
| **速度** | ~2s/订单 | ~30-60s/订单 | **~0.1s/订单** |
| **解的质量** | 依赖运气 | H01 最优, H02 差 | **三个订单均接近最优** |

**核心发现**：Beam Search 的利润排序机制在 H02 场景下导致 J01/J02 被完全排斥（利润密度最低），净利润仅 216,240。多策略贪心通过尝试"先放 J05 再放 J01/J02"的顺序，找到净利润 295,320 的解，提升了 36%。
